# PPT 咨询报告生成 Skill

## 用途

将输入的 PPT 文字内容或 PPTX 草稿，生成/重排为咨询公司风格的成品 PPTX：
- 所有元素原生可编辑（文本框、形状、表格，非图片贴图）
- 版式风格参考 ILLUMINERA（青色）/ IQVIA（深蓝）两套母版
- 输出语言：用户指定，默认和输入的主要语言一致（输入可为中文或中英混合）

## 输入

两种形式均可：
1. **文字稿**：markdown 或纯文本，含每页论点与论据
2. **PPTX 草稿**：已有页面，需要翻译/重排/统一风格

## 输出

成品 `.pptx` 文件 + 每页渲染截图（QA 用）

## 工具链

| 工具 | 用途 |
|---|---|
| python-pptx（managed Python 自带） | 读取/构建/修改 PPTX，主力生成引擎 |
| OfficeCLI（已装于 npm-global PATH） | 渲染截图供视觉检查、`view issues` 自动检测溢出/越界、dump/batch 克隆模板 |
| 本 skill 的 assets | 设计系统令牌、版式目录、翻译记忆 |

工作目录约定：运行脚本时将工作目录设为当前工作区（输入/输出文件所在目录）；skill 内的 `scripts/`、`assets/` 路径一律相对于本 SKILL.md 所在目录解析。OfficeCLI 在 git bash 中需先 `export PATH="/d/KimiData/daimon-share/daimon/npm-global:$PATH"`。

## 主流程

### 第 0 步：判定输入类型与任务模式

- 输入是 .pptx → **草稿模式**：提取内容与结构 → 翻译（如有需要）→ 判断版式是否已合规
  - 版式已合规（元素齐全、无溢出、风格正确）→ 保留版式，仅替换文本（保险路径）
  - 版式不合规 → 进入版式决策，用构建器重排该页
- 输入是文字稿 → **生成模式**：内容结构化 → 版式决策 → 构建

### 第 1 步：内容理解

运行 `scripts/inspect_deck.py <输入.pptx>` 提取内容模型：
每页的 action title（核心论点）、内容块（对比/要点/表格/数据）、逻辑关系。

对文字稿：按"一页一论点"切分，识别论据类型：
- 对立概念并列 → 对比型
- 多主体×多阶段 → 矩阵型
- 数字+解读 → 图表洞察型
- 流程递进 → 流程型

### 第 2 步：版式决策

对照 `assets/版式目录.md` 的 13 个版式族（F01-F13），按内容特征匹配。
匹配表（摘要）：
- 封面/目录/章节分隔 → F01/F02/F03（按位置自动安排，不占用内容页）
- 2-3 个对立/并列概念块 → F07 双栏对比
- 多行×多列结构化信息 → F08 表格矩阵
- 流程、阶段推进 → F09 流程图
- 大数字/图表 + 解读 → F10 图表洞察
- 结论罗列 → F12 总结横条
- 拿不准 → F06 标准内容页（action title + bullet，最通用）

容量规则：单页 bullet ≤ 6 条、每条 ≤ 2 行；超出 → 拆页（续页标题加 "(cont.)"）。

### 第 3 步：构建

- 草稿模式（保险路径）：**直接对原始草稿操作**（勿经过 OfficeCLI dump→batch 回环，回环会丢失个别图片），用 python-pptx 按翻译映射替换文本，不动坐标。
- 生成模式/重排：从模板资产实例化页面 → 调用 `scripts/builders.py` 中对应版式族构建器（13 族全覆盖，函数清单见 `assets/版式规格.md` 末尾）。
- **画布缩放**：两套模板物理尺寸不同（illum 25.4×14.29cm，iqvia 33.87×19.05cm）。builders.py 内部用 `U()`/`S()` 按 `new_deck()` 时检测到的画布自动缩放坐标与字号，调用方一律使用设计坐标（33.87 基准）。
- 模板资产（已预置，勿运行时重新克隆）：
  - 风格 A：`assets/template_illum.pptx`（5 母版 55 版式，ILLUMINERA 青）
  - 风格 B：`assets/template_iqvia.pptx`（2 母版，IQVIA 深蓝）
  - 补充模板方法（剥离法，秒级）：python-pptx 打开参考报告，`drop_rel` 删除全部 slide 关系后保存；优于 OfficeCLI 整册 batch（41 页实测 >45 分钟）
- 风格 A 版式名与版式族对照（实例化时按名取用）：
  - `1_封面01`/`封面01` → F01 封面；`2_目录02` → F02 目录；`分割页03` → F03 章节分隔；`内页_单行标题01`/`2_内页_单行标题01` → F06 内容页；`内页_双行标题02` → F06 变体
- 锚点（所有版式共享，风格 A 实测值）：
  - 页面 33.87 × 19.05 cm（16:9）
  - 标题占位符：x0.94 y1.69 w30.74，单行 action title
  - 章节标签条：y4.39 h0.85，下压横线 y4.82
  - Implications 底栏：y15.63 h2.07（标签块 w3.9 + 内容块）
  - 左右边距 1.48 cm，内容区 y5.65 ~ y15.4

### 第 4 步：质检闭环（必做）

1. `officecli view <成品> screenshot -o qa/p.png --page 1-N` 渲染全部页面
2. `officecli view <成品> issues --json` 自动检测文字溢出/形状越界
3. 人工视觉检查每页：溢出、重叠、对齐漂移、字号不一致、中英混排残留
4. 发现问题 → 修复（字号降级阶梯 14→12→10.5pt，或拆页）→ 回到第 1 步复检

### 第 5 步：交付

成品保存到工作区根目录，命名 `<原名>_EN.pptx`（或按用户指定）。
报告：页数、修改点清单、遗留问题（如有）。

## 翻译规范

- 医药咨询术语按行业惯例（如 科室=department, 挂网价=list price, 集采=VBP）
- 保留品牌名/药品名/方案编号不译（MK-3000、HS-20093、Eylea）
- 剂量缩写不译（Q8W、BCVA）
- 中文标点转英文标点，全角转半角
- 翻译映射存 `assets/translation_maps/`，可复用

## 已知限制

- 复杂图表（原生 PPT 图表对象）的重建支持尚不完整，遇图表优先保留草稿原对象
- OfficeCLI `view issues` 对椭圆内文字的可用面积按"外接框 71%×71% 内接矩形"估算，小徽标（直径 <0.5cm 实际尺寸）易误报溢出；徽标直径建议 ≥0.6cm 实际尺寸或字号降到 7pt
- 英文译文通常比中文长 30-80%，翻译后必跑 QA 闭环（演示文稿7 实测触发过表格溢出）
